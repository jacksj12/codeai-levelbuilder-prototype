# Supported native transfer adapter — November 19, 2026

This is a restricted native DOM adapter, not a complete native lesson importer. It supports existing lesson title/front-matter text; existing activity title and whole-minute duration; existing section title, duration, guidance and remarks; and append-only new sections and five callout types. Ordinary staging remains unsaved; the separately approved four-link save branch is described at the end of this document. Shared-resource creation, image upload and general publishing are unsupported.

The user clarified that the already-assigned sandbox is separate from the official source editor and is the intended unsaved test destination. No additional sandbox is required. Official sources remain read-only. The sandbox's saved content must remain intact unless a later concrete save is explicitly authorized.

## Implementation

- `native-dom-adapter.mjs` contains a self-contained function serialized into the selected tab by the companion. It checks the exact sandbox host/editor aliases and bootstrap lesson identity before reading or acting. Official or unknown lessons are refused. A separate strictly loopback fixture guard permits only the engineering fixture page.
- Current editable controls must agree with the native serialized activity state. Ambiguous, hidden, disabled, read-only or uncommitted fields block staging. Open native dialogs and inline objective editing also block it. Vocabulary comes from the current table rather than saved bootstrap assumptions.
- Current unrelated controls/tables, original bootstrap evidence, entity identities, objective tags, resource/vocabulary data, level variants, callouts and other unmanaged activity/section properties are protected separately from editable scalar values. Authentication/password fields are excluded from capture.
- Each field action checks a fresh capture digest and its exact original value, uses the native input/checkbox event path, then reads current state again. The shared runner verifies the complete expected checkpoint, including unrelated evidence, before continuing. No private React store or hidden input is written.
- Native capability preflight covers the whole plan before mutation. Appending activities/resources; changing existing callouts, objectives, vocabulary or level associations; fractional minute values; and all other unsupported operations block the entire run. Appended sections and callouts use a dedicated native transfer runner that checkpoints generated identities. Supported prefixes are not partially applied when later actions are unsupported.
- The extension offers before/after review, exact-content keep/replace decisions, bounded runs, Stop, retained checkpoints/history and report download. It checks that the captured tab remains active. It does not include a Save action. Comparison uses the shared planner. The native transfer runner checkpoints generated identities and preserved evidence for scalar and supported append operations.
- Reopening a popup can resume when native unsaved content is still present. Reloading the native page discards unsaved content; a later journal then fails closed instead of blindly replaying lost work.
- A literal visible native zero-minute value remains distinct from blank. Converting it to an untimed blank requires an explicit reviewed clear. Legacy zero durations in older review exports still normalize to the local review editor's blank-display meaning.
